# 웹 게임 UI 원칙

- 사용자가 요청한 기준: UI·수치·버튼·메뉴·능력치·장비·상태·판정 결과·설정에는 이순신체를 쓰지 않는다. 한글 전체를 지원하는 Noto Sans KR 기반 `--ui-font`를 사용한다.
- 이순신체는 사건 제목, 실제 이야기 본문과 연대기의 사건 기록에만 명시적으로 적용한다. 부모 컨테이너에 적용하여 버튼이나 정보로 상속시키지 않는다.
- 플레이 화면에 장식용 문구나 반복되는 감성 부제를 추가하지 않는다. 삭제한 ‘여행자의 메모’, ‘모든 만남이 같은 결말로 이어지지는 않는다’ 같은 안내·격언을 다른 표현으로 되살리지 않는다.
- 표시할 텍스트는 실제 이야기, 현재 상태, 행동, 비용, 조건, 결과, 필요한 조작 안내에 한정한다. 같은 정보를 여러 영역에 반복하지 않는다.
- 승인된 시안은 3번: 가로 메뉴, 오른쪽의 작은 상태/능력치 표. 이후 사용자 요청에 따라 삽화에 이벤트 영역의 넓은 왼쪽 공간을 배정하고, 본문·선택지는 오른쪽 읽기 열에 모인다. 긴 내용의 페이지 이동 중에도 삽화는 유지한다. 능력치 6종은 항상 표시하고 아이콘·색으로 구분한다. 모바일에서는 상단의 3열 2행으로 접는다.
- 게임 제목은 영어 ARVITO이며 제목에만 UnifrakturCook 중세풍 서체를 쓴다.
- 게임 화면은 실제 뷰포트 높이에 맞춘다. 긴 내용은 페이지로 나누고, 단순 overflow:hidden으로 본문/선택지를 잘라내거나 화면 전체를 축소하지 않는다.
- 한글 웹폰트를 교체할 때 현재 문구만으로 만든 작은 글자 집합을 사용하지 않는다. 최소 현대 한글 11,172음절을 지원하는지 확인한다.

- 사용자는 이벤트를 처음부터 다시 만들기로 했다. `editor.html`의 빈 작업장에 새 사건을 작성하며, 기존 `web/events.mjs`의 100개 사건은 참고 자료와 현재 게임 콘텐츠로 보관한다. 상황에 없는 전제를 결과에 갑자기 추가하거나, 후속 장면을 독립 추첨하여 맥락을 끊지 않는다. 선택은 구체적인 행동이며 비용·판정·전투 여부를 알 수 있어야 한다. 실패 결과도 사건 자체의 원인과 이어져야 한다.

- 삽화는 전체가 보여야 한다. 여백을 없애기 위해 cover 방식으로 확대하거나 가장자리를 자르지 않는다. 원본 비율을 유지하며 프레임 안에 들어가는 가장 큰 정수 물리 픽셀 배율로 표시한다.

- 이벤트 작업장은 실제 플레이 저장을 읽거나 덮어쓰지 않는다. 편집 초안은 별도 키로 저장하고 게임에 자동 반영된다고 표시하지 않는다. 새 이벤트는 완결형으로 작성하고, 미완성 초안의 저장·백업은 허용하되 검증되지 않은 완성본 내보내기는 막는다.

- 사용자가 선택한 전투 판정은 d20 + 능력치 보정 대 방어도다. 새 전투에는 기본 d20 규칙을 적용하며 저장된 구형 진행 중 전투는 규칙이 바뀌지 않도록 유지한다. 주인공만 직접 조작하고 동료는 자동 행동한다. 전투 실험실은 플레이 저장 및 이벤트 초안과 별도이며 조정값을 실제 게임에 자동 배포하지 않는다.
